## 1. Objectifs des Missions LOT-003 et LOT-003.1

Faisant suite à la validation du **LOT-002** (Hardening Serveur & Tests de Régression API), la mission **LOT-003** et son addendum de clôture **LOT-003.1** avaient pour mandat exclusif de sécuriser et fiabiliser les flux réseau, l'authentification OAuth SSO et la couche de proxying ESI avant tout refactoring d'envergure :

1. **Sécurisation OAuth & EVE SSO (Anti-CSRF & Anti-Replay)** :
   * Rendre obligatoire le paramètre `state` lors de l'échange de jeton (`POST /api/auth/token`).
   * Rejet immédiat de tout appel sans `state` (`MISSING_STATE`), avec état vide ou avec état invalide/expiré (`INVALID_OR_EXPIRED_STATE`, `EXPIRED_STATE`).
   * Consommation unique et suppression atomique du jeton `state` pour prévenir toute attaque par rejeu.
   * Extraction automatique et transparente du `code` et du `state` lorsque l'utilisateur colle une URL complète de callback.
2. **Neutralisation XSS en Contexte de Script (`/auth/callback`)** :
   * Création et application du sérialiseur sécurisé `safeJsonStringify` pour neutraliser les injections de balises fermantes `</script>` et les caractères spéciaux (`<`, `>`, `&`, `\u2028`, `\u2029`).
   * Échappement HTML strict via `escapeHtml` pour tout le contenu injecté dans le DOM textuel (`&`, `<`, `>`, `"`, `'`).
3. **Politique CORS Restrictive & Whitelist d'Origines** :
   * Remplacement de la politique réflexive par une whitelist explicite via l'utilitaire `isAllowedOrigin`.
   * Origines autorisées : origines locales (`localhost`, `127.0.0.1`), conteneurs AI Studio (`*.run.app`, `*.google.com`, `*.aistudio.google.com`), domaines configurés via `ALLOWED_ORIGINS` / `EVE_CALLBACK_URL`, et même origine (`Host`).
   * En-tête `Vary: Origin` pour garantir l'absence de mise en cache polluante.
   * Rejet HTTP 403 Forbidden sur les requêtes preflight `OPTIONS` provenant d'origines non autorisées.
   * En-tête `Access-Control-Allow-Credentials: true` strictement réservé aux origines validées par la whitelist.
4. **Validation Fine des Entrées et Gardes-Fous API** :
   * `/api/types/lookup/:id` et `/api/types/search` : validation numérique, IDs positifs, bornage de `limit`.
   * `/api/markets/:regionId/orders` et `/api/markets/:regionId/history` : validation stricte de `regionId`, `type_id`, `page` (> 0), et `order_type` (`all`, `buy`, `sell`).
   * `/api/character/:id/*` : validation de `characterId` (entier positif EVE) et protection par en-tête `Authorization`.
   * `/api/universe/location/:id` : validation de `locationId` (entier positif).
5. **Hardening du Client ESI & Résilience Réseau** :
   * Respect strict du budget d'erreur ESI : arrêt immédiat des retries si `x-esi-error-limit-remain <= 0`.
   * Détection et respect de l'en-tête `Retry-After` sur les réponses HTTP 429 / 420.
   * Gestion d'abandon sur timeout explicite (HTTP 504 Gateway Timeout).
   * Restriction des retries automatiques aux erreurs transitoires serveur (502, 503, 504) — aucun retry sur erreurs client 4xx.
   * Infrastructure d'injection de mocks hors-ligne (`setGlobalEsiMock`) permettant des tests unitaires et d'intégration 100% déterministes et indépendants du réseau.
6. **Prévention des Fuites Mémoire Serveur** :
   * Plafonnement strict du cache en mémoire des ordres et historiques ESI (`MAX_CACHE_ENTRIES = 5000`) avec éviction FIFO explicite basée sur l'ordre d'insertion et expiration TTL.
7. **Suites de Tests Automatisés et Couverture** :
   * `server/__tests__/security_hardening.test.ts` (25 tests).
   * `server/__tests__/esi_hardening.test.ts` (9 tests).
   * Intégration complète dans les scripts npm et le CI GitHub Actions.

## 2. Détail des Implémentations LOT-003 & LOT-003.1

### 2.1 Sécurisation OAuth SSO & Callback (`server/routes/auth.ts`, `server/utils/authUtils.ts`)
* **Obligation stricte du paramètre `state` (`POST /api/auth/token`)** :
  ```ts
  if (!state || typeof state !== 'string' || state.trim().length === 0) {
    return res.status(400).json({
      error: 'MISSING_STATE',
      message: 'The state parameter is mandatory to prevent CSRF attacks.',
    });
  }
  ```
* **Vérification cryptographique et consommation unique** :
  * Validation du format hexadécimal 64 caractères.
  * Vérification de présence dans `activeOAuthStates` et contrôle de péremption (`STATE_TTL_MS = 600000`).
  * Suppression atomique immédiate du jeton : tout rejeu ultérieur est immédiatement rejeté avec `INVALID_OR_EXPIRED_STATE`.
* **Sanitisation Anti-XSS en Contexte de Script (`safeJsonStringify`)** :
  ```ts
  export function safeJsonStringify(obj: unknown): string {
    return JSON.stringify(obj)
      .replace(/</g, '\\u003c')
      .replace(/>/g, '\\u003e')
      .replace(/&/g, '\\u0026')
      .replace(/\u2028/g, '\\u2028')
      .replace(/\u2029/g, '\\u2029');
  }
  ```
  * Empêche toute rupture prématurée de balise `</script>` dans la page HTML de callback SSO.

### 2.2 Politique CORS Restrictive Whitelistée (`server.ts`, `server/utils/authUtils.ts`)
* **Utilitaire `isAllowedOrigin`** :
  * Valide l'en-tête `Origin` contre la même origine (`Host`), les environnements de développement locaux (`localhost`, `127.0.0.1`), les domaines de redirection EVE SSO configurés, et les regex autorisées pour Google Cloud Run / AI Studio (`*.run.app`, `*.google.com`, etc.).
* **Comportement du middleware CORS** :
  * Si l'origine est dans la whitelist :
    * `Access-Control-Allow-Origin: <origin>`
    * `Access-Control-Allow-Credentials: true`
    * `Vary: Origin`
    * Réponse HTTP 204 sur preflight `OPTIONS`.
  * Si l'origine n'est pas autorisée :
    * Preflight `OPTIONS` : rejet HTTP 403 avec code d'erreur `CORS_ORIGIN_NOT_ALLOWED`.
    * Requêtes simples : omission stricte des en-têtes CORS (aucun header `Access-Control-Allow-Origin` ni `Access-Control-Allow-Credentials`).

### 2.3 Hardening ESI et Résilience (`server/utils/esiClient.ts`)
* **Budget d'erreur ESI (`x-esi-error-limit-remain`)** :
  * Si le compteur ESI tombe à zéro ou moins, la boucle de retry s'interrompt immédiatement pour protéger le quota et l'IP du client.
* **Respect strict de `Retry-After` sur HTTP 429** :
  * Temporisation respectant le temps d'attente imposé par CCP ESI.
* **Timeout Abort propre** :
  * Interruption via `AbortSignal.timeout` et transformation en erreur HTTP 504 explicite.
* **Mocks Déterministes Globaux** :
  * `setGlobalEsiMock` permet l'isolation hermétique des tests d'intégration sans aucune dépendance envers le réseau externe.

## 5. Addendum — CI Regression Fix (Restauration du Lockfile npm)

### 5.1 Contexte et Détection de Régression
Le commit LOT-003.1 (`cf80847b293f98450e4a61ddd2e8034e9f82b012`) avait accidentellement supprimé `package-lock.json` au profit d'un fichier résiduel `bun.lock`.
Or, le workflow GitHub Actions (`.github/workflows/ci.yml`) s'appuie explicitement sur :
```yaml
- name: Setup Node.js 22
  uses: actions/setup-node@v4
  with:
    node-version: 22
    cache: 'npm'

- name: Install dependencies (clean install)
  run: npm ci
```
L'absence de `package-lock.json` cassait le principe d'installation déterministe sous `npm ci` et menaçait la reproductibilité de la chaîne CI.

### 5.2 Actions de Résolution Appliquées
1. **Suppression du lockfile concurrent** : Élimination définitive de `bun.lock` (résolvant formellement `ISSUE-005`).
2. **Restauration du Lockfile Canonique** : Génération stricte de `package-lock.json` (lockfileVersion 3) basée sur le `package.json` et les versions exactes déjà installées et validées dans `node_modules`.
3. **Validation `npm ci`** :
   - `npm ci --dry-run` : Succès (0 vulnérabilité).
   - `npm ci` : Installation propre et déterministe de 262 packages en 19 secondes.
4. **Vérification d'absence de modifications parasites** : Aucun changement de version dans `package.json`, aucune mise à jour de dépendances superflue.
